# 8051 — educational model

## ⚠️ Simplified implementation for learning — not production-compatible code

The Intel 8051 module of PubLab is a **teaching model of a historical
architecture**, not an emulator and not a development tool for real 8051
hardware.

- A program that runs here is **not** guaranteed to behave the same way on a
  physical 8051, and must never be used as a reference for firmware,
  certification, timing analysis or any production decision.
- Only an explicitly documented subset of the instruction set will be
  modelled — the subset the laboratory's experiments need. What is outside
  that subset is **absent, not approximated**.
- Peripherals (ports, timers, UART) will be marked `conceptual` or
  `based on <specific part>`. PubLab does not invent addresses, registers or
  behaviours and present them as real hardware.
- Cycle counts, timing and electrical behaviour are **not** modelled.

## Status: scope approved, not implemented

Nothing of the 8051 exists in the code yet. This page is the full scope,
marked item by item as real architecture or educational abstraction (Rule 7
of the specification), approved before any code is written. Implementation
proceeds in stages, each with its own tests, the same way Advanced Mode
(phase 8) was built in stages A-C.

- **Stage A** — core: registers, register banks, PSW, Internal Data Memory,
  Code Memory, `MOV`/arithmetic/logic instructions, jumps, `CALL`/`RET`.
- **Stage B** — the `P0` I/O port, as a true readable/writable peripheral.
- Timers (`T0`/`T1`), the UART, and the other ports (`P1`-`P3`) are **not
  planned for phase 9** — see "Explicitly out of scope" below.

## Registers

| name | width | real or abstraction |
|---|---|---|
| `A` (accumulator) | 8-bit | real — SFR address `0xE0` |
| `B` | 8-bit | real address (SFR `0xF0`), but **repurposed**: real hardware uses `B` as the second operand/high-result register for `MUL`/`DIV`, which this model does not implement (see "Explicitly out of scope"). Here `B` is modelled as a second general register with no special instruction behaviour. |
| `R0`-`R7` | 8-bit each | real — not a flat register file: they are **the first 8 bytes of whichever Internal Data Memory bank `PSW.RS1:RS0` currently selects** (see "Memory" below). Reading `R3` after switching banks reads a different byte of real memory — that aliasing is the actual teaching point of this architecture, and the model must preserve it exactly, not fake it with a separate register file. |
| `PC` | 16-bit | real |
| `SP` | 8-bit | real — **and it grows upward**, the opposite of PubVM's stack. `PUSH` increments `SP` first, then writes at the new `SP`; `POP` reads at `SP`, then decrements. Real silicon resets `SP` to `0x07`; this model does the same. |
| `DPTR` (`DPH`:`DPL`) | 16-bit | real, but **narrowed**: real hardware uses `DPTR` for `MOVX` (external data memory, which this model has no concept of) and `MOVC` (reading Code Memory as data, for lookup tables). Only the `MOVC`-style read is modelled; `MOVX` is absent, not approximated, because there is no external memory to point it at. |

`A` and `B` are *not* reachable as a memory-mapped SFR address in stage A
(real hardware allows `MOV 0xE0, #5` as a byte-address alias for
`MOV A, #5`) — only the named-register mnemonic form is implemented.
Memory-mapped SFR access is a possible later stage, not stage A.

## PSW (Program Status Word) and flags

| bit | name | real or abstraction |
|---|---|---|
| 7 | `C` (carry) | real |
| 6 | `AC` (auxiliary carry) | real — half-carry out of bit 3, set by `ADD`/`ADDC`/`SUBB`, the same way real hardware computes it (relevant to BCD arithmetic, which this model does not otherwise implement — `AC` is still computed correctly even though no BCD instruction uses it yet) |
| 5 | `F0` | real bit, general-purpose user flag — modelled as a plain readable/writable bit; no instruction in stage A sets it automatically |
| 4-3 | `RS1:RS0` | real — selects the active register bank (0-3) for `R0`-`R7` |
| 2 | `OV` (overflow) | real — signed overflow, computed the same way PubVM's `O` flag is (same operand/result sign reasoning), but on `ADD`/`ADDC`/`SUBB` only |
| 1 | (reserved) | real hardware leaves this user-definable; this model always reads it as `0` and ignores writes to it, which is a documented simplification (real parts vary here) |
| 0 | `P` (parity) | real — **recomputed after every write to `A`**, not just after arithmetic: it always reflects the current parity of the accumulator's bits, exactly like real hardware |

Unlike PubVM, the 8051 PSW has **no persistent Zero flag**. `JZ`/`JNZ` test
the live value of `A` at the moment the jump executes, not a flag a previous
instruction left behind. This is a real, well-known difference between the
two architectures, and it is one of the comparisons phase 11 (architecture
comparison) is for.

## Memory

```
Code Memory           4 KB     (real parts range from 4 to 64 KB; this
                                model uses 4 KB — simplification, documented
                                here — enough for every example the
                                laboratory ships)
Internal Data Memory   128 bytes, real size for the classic 8051
```

Internal Data Memory layout (all real):

```
0x00-0x1F   4 register banks (R0-R7), 8 bytes each — selected by PSW.RS1:RS0
0x20-0x2F   bit-addressable memory
0x30-0x7F   general-purpose RAM
```

**Bit-addressable access (`SETB`/`CLR`/`MOV` on a single bit) is not
implemented in stage A.** The `0x20-0x2F` region exists and is real memory
in this model, reachable with ordinary byte instructions — only the
dedicated bit-addressing instructions are deferred. This is listed
separately from "explicitly out of scope" because it is real architecture,
just not yet implemented, the same way PubVM's phase 8 stages left later
mnemonics explicitly recognised-but-not-implemented rather than unknown.

SFR space (`0x80-0xFF` on real hardware) is **not** modelled as a memory
region in stage A: `PSW`, `SP`, `A`, `B` and (stage B) `P0` are reached only
through their named-register mnemonics, never through a byte address in that
range. This is a simplification over real hardware, where many SFRs really
are memory-mapped.

## Instructions — stage A

Real 8051 mnemonics, a deliberately small subset:

| instruction | forms | notes |
|---|---|---|
| `MOV` | `MOV r, imm` · `MOV r, r` · `MOV r, direct` · `MOV direct, r` | `direct` is a Internal Data Memory address, real addressing mode |
| `ADD`, `ADDC` | `op A, r` · `op A, imm` | real mnemonics; the 8051 has no plain register-to-register `SUB` |
| `SUBB` | `SUBB A, r` · `SUBB A, imm` | real — "subtract with borrow"; there is no borrow-less `SUB` on real hardware either |
| `ANL`, `ORL`, `XRL` | `op A, r` · `op A, imm` | real mnemonics (not PubVM's `AND`/`OR`/`XOR` spelling) |
| `INC`, `DEC` | `op r` | real |
| `JZ`, `JNZ` | `op addr` | real — test `A`, not a flag (see "PSW" above) |
| `JC`, `JNC` | `op addr` | real — test the `C` flag |
| `JMP` | `op addr` | **simplification**: real hardware offers `AJMP`/`LJMP`/`SJMP`, three forms distinguished by jump range (an encoding-density concern of the real instruction set, not a teaching point for this lab). One `JMP` reaching all of Code Memory replaces the three. |
| `CALL`, `RET` | `op addr` / `op` | same simplification as `JMP`: real `ACALL`/`LCALL` collapse to one `CALL` |
| `PUSH`, `POP` | `op r` | real mnemonics; real hardware pushes/pops a *direct address*, not only a named register — narrowed to the registers this model names, consistent with "`A`/`B` are not reachable as an SFR address" above |
| `HALT` | `op` | **not a real 8051 instruction.** Real hardware has no halt — a finished program is conventionally an infinite self-jump (`HERE: SJMP HERE`). PubLab adds an educational `HALT`, the same way `PRINT` is already an educational PubVM instruction and not a real CPU one (section 13 of the specification) — so the laboratory has an honest way to end a step-through session. |
| `PRINT` | `op r` | **not a real 8051 instruction**, reused verbatim from PubVM for the same reason `HALT` is added: an educational way to observe a register's value as output, exactly like PubVM's `PRINT` (same justification, same wording, section 13). |

## Explicitly out of scope for phase 9

Listed so the boundary is on record, not implied by silence:

- **`MUL`, `DIV`** — the instructions that give `B` its real purpose. Absent,
  not approximated.
- **Bit-addressing instructions** (`SETB`, `CLR`, bit-level `MOV`/`ANL`/`ORL`
  on `0x20-0x2F`) — the memory region is real; the instructions that address
  individual bits are not implemented yet.
- **`MOVX`** (external data memory) — there is no external memory concept in
  this model.
- **`MOVC`-based lookup tables, `XCH`, `SWAP`, `RL`/`RR`(C)`, BCD
  instructions (`DA`)** — real 8051 instructions, simply not in the stage A
  subset.
- **Interrupts** (`INT0`/`INT1`, timer interrupts, serial interrupt, `IE`,
  `IP`) — a real, significant part of the 8051 programming model, out of
  scope for phase 9 entirely. If ever modelled, it needs its own scope
  document under this same Rule 7 discipline.
- **Timers `T0`/`T1`, the UART, ports `P1`-`P3`** — only `P0` is planned
  (stage B). The others are absent, not approximated, until a future phase
  explicitly scopes them the same way this page scopes `P0`.
- **Cycle counts, timing, electrical behaviour** (quasi-bidirectional port
  electrical model, oscillator frequency) — never modelled, as stated at the
  top of this page.

## Peripherals — stage B

| name | model |
|---|---|
| `P0` | **based on the classic 8051's `P0`**: an 8-bit, byte-addressable, directly readable and writable register. Real `P0` is electrically quasi-bidirectional (an internal pull-up, open-drain output, and reading it reads the pin state, not the last value written, when configured as input) — none of that electrical nuance is modelled. This model's `P0` behaves as a plain read/write register: whatever was last written is what is read back. That gap is deliberate and stated here, not left for the reader to discover. |

`P1`, `P2`, `P3` are reserved names, following the same pattern PubVM's
Advanced Mode used for not-yet-implemented mnemonics/registers: recognised
by the assembler and rejected with an honest "not implemented in this
phase" diagnostic, never treated as an unknown identifier.
